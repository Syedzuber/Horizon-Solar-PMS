{% extends "base.html" %} {% comment %} Raise a change request — a design change request from the site's PM or one of its coordinators, a BOQ change request from SCM (session B3b, D-18). Reachable by whoever permissions.user_can_request_design_change() admits: the assigned PM and the site's Project Coordinators through user_can_manage_project(), and any SCM user (session 3.1c-i, D-b). THE WINDOW IS DECIDED IN THE VIEW, NEVER HERE. `window_open` is design_views.change_request_window_open() — the predicate the POST enforces — and `closed_reason` is the code _change_request_refusal() gives the POST. The branches below render from those two values and re-derive nothing: locked the site is in a LOCKED procurement group — refused for everybody scm_before_release SCM, and the design is not released yet qc_not_started the PM, before QC has started on the current attempt stage the PM, at a status outside the window (e.g. with the PM for approval) A site in a DRAFT procurement group stays in it until the Design Head ACCEPTS the request (3.1c-i, Q2); `draft_group` names the group so the note can say so. SESSION B2a — THE SCM ROUTE. An SCM-raised request starts WITH THE PM (`raise_goes_to_pm`), unless the site has no PM and no active coordinator (`raise_skips_pm`, Q5), when it goes straight to the Head and the row says so (`cr.skipped_pm`, read off the raise line's action_code). On a `with_pm` row the PM and active coordinators get Forward / Reject (`can_pm_triage`) and SCM gets Withdraw (`can_withdraw`) — the predicates the POSTs enforce. EVERY VERDICT HAS ITS OWN BRANCH; the last `else` shows the stored label and nothing more, so no value can fall into "Awaiting the Design Head". SESSION B3b — THE KIND. `raise_goes_to_pm or raise_skips_pm` is exactly "not user_can_manage_project" for this viewer (design_change_request_form), and only a manager or SCM can open this page, so it means "this viewer raises as SCM": the button reads BOQ.
