{% comment %} Attempt history for one site — every attempt, why it opened, how it ended. THE TWO REWORK LOOPS ARE DELIBERATELY DIFFERENT COLOURS. `qc_failed` is red because the package was wrong; `pm_change_request` is amber because the brief changed. They are the same event shape and different causes, and a screen that renders them identically throws away the only signal that tells a design-quality problem from a requirements problem. Note the PM-change-request rows show "not judged" rather than a verdict: that attempt was closed without QC ever ruling on it, and its qc_verdict stays 'pending' forever by design. Rendering that as "pending" alone would read like a review still in progress. PART 9 ADDED THE SECOND GATE, so each attempt now carries up to two verdicts and they are rendered as two chips side by side. The Head's chip appears only where Design QC PASSED — a QC failure ends the attempt and the Head never sees it, so head_verdict stays 'pending' on those rows meaning "not judged", exactly as qc_verdict does on a change-request row. A `head_reviewed_at` with no `head_reviewed_by` is a pre-Part-9 row carried forward by migration 0055 and says so on screen rather than showing a blank name. Shared by qc_review.html, change_request.html and site_workspace.html, so the designer, the Head and the PM all read the same history in the same shape. {% endcomment %}
