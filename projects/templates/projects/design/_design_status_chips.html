Part 3 settled that no status value is invented for "Arka approved, artifacts outstanding": the site stays at `arka_submitted` and the VERDICT disambiguates. Part 9 kept that, so a site whose Arka has cleared both gates still stores `arka_submitted` — and a chip reading "Arka submitted" there is actively misleading. It tells a Design Head the Arka is still waiting on somebody when he has already approved it, which is exactly how a reviewer ends up hunting a site that is in fact sitting with the designer. So the label follows what design_metrics._classify() computes for the same site rather than the raw status: `arka_approved` when head_verdict is approved, `arka_submitted` otherwise.
