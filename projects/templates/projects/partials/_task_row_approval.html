{% comment %} Two-step completion (2.1), COMPACT — the phase-list row's version of the panel that lives full-size on task_detail as `_task_approval.html`. WHY A SECOND, SMALLER PARTIAL AND NOT AN INCLUDE OF THE BIG ONE. Two reasons, both measured before this file was written: QUERIES. `_task_approval.html` is fed by `_task_approval_context()`, which calls `user_can_submit_task_for_approval()` and `user_can_approve_task()` — and both route through `user_can_manage_project()`, whose coordinator arm is a `.filter().exists()`. That is one query per call, i.e. two per row, on a list of 23 rows for a stock OPEX site and unbounded in general. The project-level half of that answer is IDENTICAL for every row and the page already holds it in `is_assigned_pm`; the only genuinely per-row half is "is this task mine", which is a comparison against an object the row has already loaded. So the authority is reassembled here from what the page has, and costs nothing. WIDTH. The panel is a `card` with a two-column body, a textarea and two buttons. Dropped into a ~12rem status cell it is the horizontal-scroll problem, not a fix for it. What a row needs is a badge and one small button. THE AUTHORITY IS THE SAME AUTHORITY, restated and not re-decided. `user_can_submit_task_for_approval()` is `task.assigned_to == profile OR user_can_manage_project()`, and `is_assigned_pm` on this page IS `user_can_manage_project(request.user, project)` — the same call, made once in the view. The test below is that OR with the expensive half substituted by the value already computed. If the two ever diverge the endpoint still refuses: this markup opens no door, it only avoids offering one that is locked. APPROVING IS NOT OFFERED HERE, deliberately. Approval moves the task to Done, so a row that approved in place would leave the status select beside it reading In Progress until the next page load — the one contradiction `_task_approval_ response.html` exists to prevent on task_detail. Submission does NOT move the status (2.1 §3), so the badge is the only thing on the row that changes and the swap below can keep it honest. The approver's controls stay on task_detail, and this row tells them the task is waiting.
