## Critical — read before writing any code

1. Read projects/supabase_storage.py before writing any upload logic.
   Use whatever client initialisation pattern already exists there.
   Do NOT create a second Supabase client. Do NOT import supabase at module level in views.py.

2. Supabase bucket is PUBLIC. Store the permanent public URL in file_url.
   Do NOT generate signed URLs. Do NOT use signed URLs anywhere.
   Public URL format: {SUPABASE_URL}/storage/v1/object/public/{SUPABASE_BUCKET}/{path}

3. Add to settings.py:
   FILE_RETENTION_DAYS = env.int('FILE_RETENTION_DAYS', default=90)
   DATA_UPLOAD_MAX_MEMORY_SIZE = 104857600
   FILE_UPLOAD_MAX_MEMORY_SIZE = 104857600

4. Supabase path convention — always use UUID prefix to prevent collisions:
   project-documents/{project_id}/{uuid}_{original_filename}
   task-attachments/{project_id}/{task_id}/{uuid}_{original_filename}

## Layer 1 — Plain English

Every role can attach files to a project (project-level) and to any specific
task (task-level). Multiple files can be uploaded in one action. Files are
stored in Supabase public bucket. Soft delete hides files from UI immediately.
A nightly management command hard deletes files soft-deleted beyond
FILE_RETENTION_DAYS (default 90 days). Only the uploader or Admin can delete.
File types restricted to documents and photos only. 20MB max per file.

## Layer 3 — User Journey

### Project-level upload
1. User opens project detail page or project overview page
2. "Upload Files" button visible to all roles
3. File picker opens — multiple selection enabled, accept attribute set to
   .pdf,.doc,.docx,.xls,.xlsx,.jpg,.jpeg,.png
4. Client-side validation on file select:
   - Extension check against allowed list
   - Size check (each file ≤ 20MB)
   - Invalid files show inline error, valid files queued for upload
5. User clicks Upload → POST to /projects/<project_id>/documents/upload/
6. Django validates server-side: extension, MIME type, size
7. Each valid file:
   - Generate UUID, build supabase_path
   - Upload to Supabase
   - Build public URL
   - Create ProjectDocument record
8. Partial failures: create records for successes, return warning for failures
9. Redirect back to page — uploaded files appear in document list

### Task-level upload
1. User opens task detail page
2. "Attach Files" button visible to all roles
3. Same file picker and validation flow
4. POST to /projects/<project_id>/tasks/<task_id>/attachments/upload/
5. Django verifies task.phase.project.project_id == project_id (cross-project guard)
6. Files uploaded, TaskAttachment records created
7. Task detail refreshes — attachment count updated, files listed

### Soft delete
1. Delete icon visible only to uploader or Admin next to each file
2. Click delete → browser confirm() dialog:
   "Delete this file? It can be recovered within 90 days."
3. POST to delete URL
4. Ownership check: uploaded_by == current_profile OR role == 'Admin'
5. Set is_deleted=True, deleted_at=now(), deleted_by=current_profile
6. Redirect — file no longer appears in any listing

### Nightly hard delete
Management command: python manage.py purge_deleted_files
- Finds ProjectDocument and TaskAttachment where:
  is_deleted=True AND deleted_at < now() - FILE_RETENTION_DAYS
- For each: delete file from Supabase using supabase_path
- If Supabase delete fails: log error, skip, continue (retry next night)
- Delete database record only after Supabase delete succeeds
- Log total purged count on completion

## Layer 4 — Edge Cases

1. Supabase upload fails — do NOT create DB record. Return error to user.
   Never store a ProjectDocument/TaskAttachment with a broken or empty URL.

2. Partial multi-file upload — 3 of 5 files succeed, 2 fail.
   Create records for the 3 successes. Return warning listing failed filenames.
   Never roll back successful uploads because one file failed.

3. Duplicate filename — UUID prefix in path prevents Supabase collision.
   Same filename from same user allowed — two separate records, different UUIDs.

4. File type spoofing — validate both extension AND MIME type server-side.
   If extension and MIME type don't match: reject with 400.

5. 20MB limit — client-side check (file.size in bytes) for UX.
   Server-side check (request.FILES) for security. Both required.

6. Cross-project task injection — in task upload view, verify
   task.phase.project.project_id == project_id from URL.
   Return 403 if mismatch.

7. Unauthorised delete — check ownership before soft delete.
   Return 403 if uploaded_by != current_profile AND role != 'Admin'.

8. Supabase delete fails during purge — log error, skip file, continue.
   Retry next night. Never let one failure stop the entire purge run.

9. Missing env vars — get_supabase_client() raises ValueError if
   SUPABASE_URL or SUPABASE_KEY missing. Upload view catches this,
   returns 500 with user-friendly message. Never crash app on import.

10. Pre-Day-7 projects — no documents or attachments.
    project.documents.filter(is_deleted=False) returns empty QuerySet safely.
    Show "No files uploaded yet" empty state with upload button.

11. PM isolation — PM can only see projects assigned to them.
    File upload and delete views must respect this: get_object_or_404
    scoped correctly for PM role, same as project_overview view.

## Layer 5 — Bug Pre-emption

### Bug 1 — Supabase client crash on missing credentials
Never initialise Supabase client at module level.
Use the lazy pattern already in projects/supabase_storage.py.
If that file uses module-level initialisation, refactor it to a function.
The app must start and serve requests even if Supabase is misconfigured —
only the upload action should fail, not the entire app.

### Bug 2 — Django request size limit blocking uploads
Default DATA_UPLOAD_MAX_MEMORY_SIZE is 2.5MB. Without the override,
multi-file 20MB uploads crash with RequestDataTooBig before the view runs.
Confirm these are in settings.py before running the session:
DATA_UPLOAD_MAX_MEMORY_SIZE = 104857600
FILE_UPLOAD_MAX_MEMORY_SIZE = 104857600

### Bug 3 — Public URL construction
Do not guess the public URL format. Build it explicitly:
```python
file_url = (
    f"{settings.SUPABASE_URL}/storage/v1/object/public/"
    f"{settings.SUPABASE_BUCKET}/{supabase_path}"
)
```
Never use the Supabase client's get_public_url() method without
verifying the returned format matches the above — different versions
of supabase-py return different formats.

### Bug 4 — File extension extraction
Always lowercase the extension before checking:
```python
ext = file.name.rsplit('.', 1)[-1].lower()
```
A file named Document.PDF must be accepted, not rejected.
Never split on '.' and take index [1] — filenames can have multiple dots.
Always use rsplit('.', 1) to get the last extension only.

## Management command

File location: projects/management/commands/purge_deleted_files.py
Create the management/commands/ directory with __init__.py files if not present.

```python
from django.core.management.base import BaseCommand
from django.utils import timezone
from datetime import timedelta
from django.conf import settings

class Command(BaseCommand):
    help = 'Hard delete files soft-deleted beyond FILE_RETENTION_DAYS'

    def handle(self, *args, **options):
        retention_days = getattr(settings, 'FILE_RETENTION_DAYS', 90)
        cutoff = timezone.now() - timedelta(days=retention_days)

        from projects.models import ProjectDocument, TaskAttachment
        from projects.supabase_storage import get_supabase_client

        doc_count = 0
        attach_count = 0

        for doc in ProjectDocument.objects.filter(
            is_deleted=True, deleted_at__lt=cutoff
        ):
            try:
                client = get_supabase_client()
                client.storage.from_(settings.SUPABASE_BUCKET).remove(
                    [doc.supabase_path]
                )
                doc.delete()
                doc_count += 1
            except Exception as e:
                self.stderr.write(
                    f"Failed to purge ProjectDocument {doc.pk}: {e}"
                )

        for attach in TaskAttachment.objects.filter(
            is_deleted=True, deleted_at__lt=cutoff
        ):
            try:
                client = get_supabase_client()
                client.storage.from_(settings.SUPABASE_BUCKET).remove(
                    [attach.supabase_path]
                )
                attach.delete()
                attach_count += 1
            except Exception as e:
                self.stderr.write(
                    f"Failed to purge TaskAttachment {attach.pk}: {e}"
                )

        self.stdout.write(
            f"Purged {doc_count} project documents, "
            f"{attach_count} task attachments"
        )
```
