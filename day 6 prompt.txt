## Feature 1 — Finance dashboard + PaymentMilestone model (1 migration)

### New model — PaymentMilestone
```python
class PaymentMilestone(models.Model):
    PENDING = 'Pending'
    INVOICED = 'Invoiced'
    RECEIVED = 'Received'
    STATUS_CHOICES = [
        (PENDING, 'Pending'),
        (INVOICED, 'Invoiced'),
        (RECEIVED, 'Received'),
    ]
    M1 = 'M1'; M2 = 'M2'; M3 = 'M3'
    NAME_CHOICES = [(M1,'M1'), (M2,'M2'), (M3,'M3')]

    project = models.ForeignKey(
        Project, on_delete=models.CASCADE, related_name='milestones'
    )
    milestone_name = models.CharField(max_length=10, choices=NAME_CHOICES)
    milestone_description = models.CharField(max_length=100, default='')
    amount = models.DecimalField(
        max_digits=12, decimal_places=2, null=True, blank=True
    )
    amount_received = models.DecimalField(
        max_digits=12, decimal_places=2, null=True, blank=True
    )
    variance_reason = models.CharField(max_length=255, blank=True, default='')
    due_date = models.DateField(null=True, blank=True)
    invoice_date = models.DateField(null=True, blank=True)
    received_date = models.DateField(null=True, blank=True)
    status = models.CharField(
        max_length=20, choices=STATUS_CHOICES, default=PENDING
    )
    created_by = models.ForeignKey(
        UserProfile, null=True, blank=True, on_delete=models.SET_NULL
    )

    class Meta:
        ordering = ['milestone_name']

    # NOTE: M1, M2, M3 milestones correspond conceptually to tasks 2, 28,
    # and 51 in the residential task template (payment trigger tasks).
    # No FK link is intentional for Phase 1 — keep execution tracking
    # (tasks) and financial tracking (milestones) separate.
    # Do NOT create a task FK here. Do NOT auto-update milestone status
    # based on task completion. The notification engine (Week 3) will
    # bridge these two systems when built.
```

Run makemigrations and migrate. Migration number will be 0013.

#### Project list table
All active/in-progress projects. Columns: Project ID, Customer,

Badge colours:
- Pending → gray (secondary)
- Invoiced → blue (primary)

### Milestone update actions — POST only

#### Mark as Invoiced
URL: /projects/<project_id>/milestone/<milestone_pk>/invoice/
Decorator: @login_required @role_required(['Finance'])
Logic: fetch milestone → verify status=Pending →
set status=Invoiced, invoice_date=date.today() → save →
redirect to finance dashboard.
One-click, no modal needed.
CRITICAL: POST with CSRF. Never a GET link that changes data.

#### Mark as Received (modal required)
URL: /projects/<project_id>/milestone/<milestone_pk>/receive/
Decorator: @login_required @role_required(['Finance'])

Trigger: Finance clicks the Invoiced badge → Bootstrap modal opens.
Modal contains:
- Milestone name and agreed amount (read-only display)
- amount_received field (decimal input, required, prefix ₹)
- variance_reason field (text input, optional,
  placeholder "e.g. customer paid partial amount")
- Submit button: "Mark as Received"

On POST: fetch milestone → verify status=Invoiced →
set status=Received, received_date=date.today(),
amount_received=form value, variance_reason=form value →
save → redirect to finance dashboard.

If amount_received == amount: no variance, clean green badge.
If amount_received < amount: variance exists, amber warning
icon appears next to badge.
If amount_received > amount: treat as overpayment, still mark
Received, show variance_reason as "Overpayment" if blank.

CRITICAL: received_date, amount_received, and variance_reason
can only be set by Finance. PM and BD cannot write to these fields.

### Panel 5 — Recent activity (all roles)
Combined list of last 5 events across:
- DueDateChangeLog: task name, old date → new date, changed by, date
- BOQRevision: event type, version, by whom, date

Combine in Python, sort by date descending, show latest 5.
Simple list — no pagination needed.

### Full view skeleton
```python
@login_required
def project_overview(request, project_id):
    project = get_object_or_404(Project, project_id=project_id)
    profile = request.user.userprofile

    # PM isolation
    if profile.role == 'PM' and project.assigned_pm != profile:
        raise Http404

    # BOQ annotation
    try:
        project.boq_status = project.boq.status
        project.boq_last_event = (
            project.boq.revisions.order_by('-revised_at').first()
        )
        project.boq_url = f"/projects/{project.project_id}/boq/"
    except Exception:
        project.boq_status = None
        project.boq_last_event = None
        project.boq_url = None

    milestones = project.milestones.all()
    phases = project.phases.prefetch_related('tasks').order_by('phase_order')

    # Recent activity — combine and sort
    from projects.models import DueDateChangeLog, BOQRevision
    due_changes = list(
        DueDateChangeLog.objects.filter(
            task__phase__project=project
        ).order_by('-changed_at')[:10]
    )
    boq_events = list(
        BOQRevision.objects.filter(
            boq__project=project
        ).order_by('-revised_at')[:10]
    )
    # Annotate type for template rendering
    for e in due_changes:
        e.event_type = 'due_date'
        e.event_date = e.changed_at
    for e in boq_events:
        e.event_type = 'boq'
        e.event_date = e.revised_at
    recent_activity = sorted(
        due_changes + boq_events,
        key=lambda x: x.event_date,
        reverse=True
    )[:5]

    return render(request, 'projects/project_overview.html', {
        'project': project,
        'milestones': milestones,
        'phases': phases,
        'recent_activity': recent_activity,
        'role': profile.role,
    })
```

## Known failure points — apply defensively throughout

1. DecimalField sum with nulls: always use
   aggregate(s=Sum('amount'))['s'] or 0.
   For Total Received use Sum('amount_received'), not Sum('amount').

2. Pre-Day 6 projects with no milestones:
   project.milestones.all() returns empty QuerySet — safe.
   Never use .get() on milestones anywhere.

3. project.boq access: always try/except in view, never in template.
   Same pattern as Day 5. Apply to project_overview view.

4. Milestone update views must be POST with CSRF token.
   Never GET links that write to the database.

5. Circular import: import PaymentMilestone inside the activation
   function body, not at module level in utils.py.

6. Mark as Received modal: the modal form must POST to
   /projects/<id>/milestone/<pk>/receive/ — not to the current page.
   Use a Bootstrap modal with action attribute set on the form,
   not on the trigger button. Verify the form action URL is correct
   before submitting — a common mistake is the modal form posting
   to the wrong URL when multiple modals exist on one page.

7. Variance calculation: do not calculate variance in the template
   using arithmetic. Annotate it in the view or on the object
   in Python:
   ```python
   for m in milestones:
       if m.amount and m.amount_received is not None:
           m.variance = m.amount - m.amount_received
       else:
           m.variance = None
   ```
